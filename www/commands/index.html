Документация Harness

Команды Harness

Стабильный человеко-машинный интерфейс: короткие команды запускают предсказуемые repository-level workflow и оставляют durable artifacts.

Bootstrap и планирование

INIT PROJECT

Однократный bootstrap из PROJECT_BRIEF.local.md. Создаёт knowledge base и initial roadmap, но не production code.

ADD STEP: <описание>

Преобразует человеческую задачу в новый STEP с scope, dependencies, acceptance criteria и verification.

PLAN STEP-NNN

Проводит pre-implementation analysis и сохраняет Implementation plan внутрь task-файла.

NEXT STEP

Read-only рекомендует следующий unblocked STEP по dependencies, priority, risk и roadmap.

STATUS PROJECT

Проверяет status projections, blockers, unblocked work и drift indicators.

Выполнение и контроль

IMPLEMENT STEP-NNN

Реализует сохранённый план в пределах task contract и запускает verification.

REVIEW STEP-NNN

Независимо проверяет task, implementation и evidence; создаёт immutable review report.

FIX STEP-NNN

Исправляет подтверждённые findings последнего применимого FAIL review.

RUN STEP-NNN

Оркестрирует PLAN → IMPLEMENT → verification → REVIEW → FIX/REVIEW → CLOSE.

AUDIT STEP-NNN

Read-only проверяет фактическое состояние; defects становятся findings/corrective work.

RECONCILE PROJECT

Ищет drift между code/tests/config и REQ/ADR/architecture/STEP/evidence.

RELEASE CHECK

Проверяет release gates: findings, requirements, migrations, tests/build, security, docs и deploy concerns.

Мелкие изменения

QUICK FIX: <описание>

Low-risk micro-change без искусственного REQ/ADR/STEP. При contract/risk change останавливается и предлагает ADD STEP.

Skills и GitHub templates

FIND SKILL: <описание>

Ищет и инспектирует repository skills, сохраняет TOP-5, ничего не устанавливает.

INSTALL SKILL: <source | #N>

Повторно инспектирует выбранный skill и устанавливает его с provenance/registry/routing.

CREATE SKILL: <описание>

Создаёт project-native skill, если подходящего upstream нет.

GENERATE GITHUB TEMPLATES

Регенерирует managed Issue Forms и PR template по фактическому tooling проекта.

Обновление Harness

CHECK HARNESS UPDATE

Read-only сравнивает BASE/OURS/THEIRS для allowlisted Harness paths и показывает blockers.

UPDATE HARNESS

После успешной проверки обновляет protocol layer по ownership policy; не делает STEP/commit/push/PR.

Git operations

GIT CHECK

Read-only preflight: branch, upstream, diff, integrity, policy и suspicious files.

COMMIT / COMMIT: <подсказка>

Создаёт только локальный безопасный Conventional Commit по git-policy.

PUSH

Публикует текущую ветку без force после divergence/safety checks.

PR

Создаёт или возвращает существующий Pull Request согласно policy.

SYNC

Fetch + ahead/behind; по умолчанию read-only, опционально только safe fast-forward.
