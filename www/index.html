Стабильный процесс. Единый dispatcher проверяет переходы, ведёт состояние выполнения и отделяет машинную механику от смысловой работы модели. Незавершённое выполнение можно безопасно восстановить из локального состояния.
Практический пример

Одна короткая команда превращается в проверяемый процесс

STEP ADD сначала создаёт сохраняемый контракт задачи. Затем STEP RUN проходит планирование → реализацию → проверку → ревью и оставляет доказательства выполнения. Все команды →

Проблема

AI пишет код. Но кто сохраняет контекст?

Без долговечных артефактов каждая новая сессия заново выясняет требования, границы задачи и причины архитектурных решений.

◎

Контекст теряется

Причины решений остаются в чатах и перестают быть доступны следующей сессии.

↔

Нет прослеживаемости

REQ, ADR, задача, код и доказательства живут отдельно — или не связаны вообще.

△

Границы задачи расползаются

Без контракта задачи агент легко меняет соседние области и усложняет ревью.

✓

Ревью превращается в доверие

Фраза «готово» не заменяет проверяемые критерии приёмки и доказательства выполнения.

Процесс

Каждый этап сохраняет контекст для следующего

Harness не требует хранить память проекта в одной AI-сессии. План, доказательства, ревью и статусы сохраняются в репозитории и становятся входом следующего этапа.

01 · ИНИЦИАЛИЗАЦИЯ
▧

Контекст

Описание проекта превращается в PROJECT, REQ, архитектуру и начальную дорожную карту.

02 · КОНТРАКТ
≡

Задача

STEP фиксирует границы задачи, зависимости, критерии приёмки и проверки.

03 · ВЫПОЛНЕНИЕ
▷

Реализация

PLAN сохраняется в задаче, затем реализатор изменяет только разрешённые области.

04 · КОНТРОЛЬ
⌕

Ревью

Независимый проверяющий оценивает код и доказательства, а не самооценку реализатора.

05 · ИСТОРИЯ
⑂

Git

Коммит, отправка изменений и PR выполняются явно после предварительных проверок и правил безопасности.

Модель контекста

Три слоя вместо одного огромного ТЗ

Протокол определяет процесс. База знаний проекта хранит требования и решения. Реализация содержит фактический код, тесты и конфигурацию. Между слоями остаются явные связи.

Среды исполнения

Один Harness — Codex и Claude Code

Протокол не привязан к одному агенту для программирования. Роли, команды и проектная память остаются общими, а модель, уровень рассуждений и разрешения конкретной среды исполнения настраиваются в файлах адаптеров.

Codex

.codex/config.toml и .codex/agents/*.toml задают роли, модель и уровень рассуждений.

Claude Code

CLAUDE.md, .claude/settings.json и .claude/agents/*.md подключают тот же протокол Harness.

Не всё требует STEP

Опечатка не должна превращаться в церемонию

Для небольших изменений с низким риском Harness оставляет короткий путь. Если правка меняет поведение, API, данные, безопасность, архитектуру или зависимости — выполнение прекращается.

Мелкая правка

PROJECT QUICK FIX: исправь опечатку…
или ручная правка → GIT CHECK → GIT COMMIT.

Изменение контракта или риска

Новая возможность или риск → STEP ADD: → контракт задачи → обычный цикл ревью и доказательств.
