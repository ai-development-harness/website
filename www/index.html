Проблема

AI пишет код. Но кто сохраняет контекст?

Без долговечных артефактов каждая новая сессия заново выясняет требования, границы задачи и причины архитектурных решений.

◎

Контекст теряется

Причины решений остаются в чатах и перестают быть доступны следующей сессии.

↔

Нет traceability

REQ, ADR, задача, код и evidence живут отдельно — или не связаны вообще.

△

Scope расползается

Без task contract агент легко меняет соседние области и усложняет review.

✓

Review превращается в доверие

Фраза «готово» не заменяет проверяемые acceptance criteria и evidence.

Процесс

Каждый этап оставляет durable handoff

Harness не требует хранить память проекта в одной AI-сессии. План, evidence, review и статусы сохраняются в репозитории и становятся входом следующего этапа.

01 · BOOTSTRAP
▧

Контекст

Brief превращается в PROJECT, REQ, architecture и initial roadmap.

02 · CONTRACT
≡

Задача

STEP фиксирует scope, out of scope, dependencies, acceptance и verification.

03 · EXECUTION
▷

Реализация

PLAN сохраняется в task, затем implementer изменяет только разрешённый scope.

04 · CONTROL
⌕

Review

Независимый reviewer проверяет код и evidence, а не самооценку implementer.

05 · HISTORY
⑂

Git

Commit, push и PR выполняются явно после preflight и policy checks.

Модель контекста

Три слоя вместо одного огромного ТЗ

Protocol определяет процесс. Project knowledge base хранит требования и решения. Реализация содержит фактический код, тесты и config. Между слоями остаются явные связи.

Практический пример

Короткая просьба становится воспроизводимой задачей

ADD STEP не пишет production code. Сначала Harness создаёт durable task contract. Затем RUN STEP может пройти plan → implementation → verification → review и остановиться при blocker.

Посмотреть весь командный интерфейс →

● ● ●project session
YOU › ADD STEP: Добавить экспорт отчётов в PDF

HARNESS › проверяю REQ / ADR / dependencies…
CREATED › STEP-024
Scope · Out of scope · Acceptance · Verification

YOU › RUN STEP-024
PLAN → IMPLEMENT → VERIFY → REVIEW
RESULT › durable evidence + review report
Не всё требует STEP

Опечатка не должна превращаться в церемонию

Для маленьких low-risk изменений Harness оставляет короткий путь. Если правка меняет behavior, API, данные, безопасность, архитектуру или зависимости — короткий путь прекращается.

Micro-change

QUICK FIX: исправь опечатку…
или ручная правка → GIT CHECK → COMMIT.

Contract/risk change

Новая capability или риск → ADD STEP: → task contract → обычный review/evidence flow.
