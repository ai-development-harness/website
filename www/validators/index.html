Документация Harness

Валидаторы и deterministic gates

Что именно Harness проверяет машинно до mutation: от структуры project knowledge и command transitions до INIT finalization, review contracts, self-update и безопасных Git-операций.

Validation layer — часть протокола, а не набор вспомогательных скриптов

Harness v0.6.0 разделяет reasoning и детерминированные инварианты. Модель анализирует требования, архитектуру и код, но структура документов, переходы команд, fingerprints, projections, review/report schema, update route и Git safety проверяются Python tooling под .harness/tools/.

Fail closed. Если обязательный Git/config/document context нельзя достоверно прочитать, gate должен вернуть BLOCKED/FAIL, а не «продолжить насколько получилось».

Главный Harness Integrity validator

.harness/tools/validate.py

Агрегирует repository hygiene, manifest/policy, project integrity, planning contracts, projections, reports, update lock и другие обязательные инварианты.

python3 .harness/tools/validate.py --mode manual
python3 .harness/tools/validate.py --mode commit
python3 .harness/tools/validate.py --mode ci

Exit codes: 0 — PASS, 1 — FAIL, 2 — BLOCKED: обязательный контекст или dependency недоступны.

Command Transition System

.harness/tools/validate-command.py

Нормализует одну Harness-команду или chain и проверяет её по .harness/command-transitions.json до запуска runtime. Неизвестный edge означает INVALID_CHAIN и ноль выполненных сегментов.

python3 .harness/tools/validate-command.py --json -- 'GIT CHECK > COMMIT > PUSH > PR'

--json нужен клиентам и tooling для machine-readable результата.

.harness/tools/check-command-references.py

Ищет deprecated или неканонические command references в живых документах.

python3 .harness/tools/check-command-references.py
python3 .harness/tools/check-command-references.py --json

DRIFT является результатом аудита и не считается runtime crash checker-а; BLOCKED используется, если документ нельзя безопасно прочитать или определить scope.

Documents, planning и project integrity

document_contract.py

Schema-v1 Markdown/frontmatter parser: duplicate sections, H1, mandatory fields, placeholders, hashes и atomic UTF-8 writes.

planning_contract.py

REQ/ADR/OQ/STEP IDs, dependencies, risk flags, mutation policy, completion proofs, OQ blockers, plan/context fingerprints и matching planning-review.

project_integrity.py

Собирает ошибки project document model в единый список для validate.py и INIT finalization.

projection_contract.py

Строит canonical projections, fail-closed обрабатывает derivation errors и требует byte-for-byte equality tracked copies.

template_contract.py

Проверяет schema-v1 project-owned templates STEP/REQ/ADR/OQ/review/report. Их изменение выполняет reconciliation, а не silent self-update.

harness_config.py

Fail-closed parser manifest/frontmatter/TOML, duplicate keys и repository-relative path containment.

Эти модули в основном являются внутренними validation boundaries. Пользователь обычно вызывает их через публичные CLI-gates.

Projection validator

.harness/tools/sync-projections.py

Строит ожидаемые SPEC.md, requirements/project STATUS, roadmap и Open Questions index из canonical REQ/STEP/OQ и сравнивает tracked copies byte-for-byte.

# read-only
python3 .harness/tools/sync-projections.py --check --json

# regeneration
python3 .harness/tools/sync-projections.py --json

В --check: 0 — PASS, 1 — DRIFT. В mutation mode: 0 — UPDATED/PASS, 2 — BLOCKED, если canonical state нельзя безопасно превратить в projection.

PROJECT INIT finalization gate

.harness/tools/finalize-project-init.py

Единственный корректный путь выставить project.initialized=true. Проверяет project overview, canonical REQ, STEP, project integrity, projections, два matching PASS INIT-review и отсутствие блокирующих project-level OQ.

# только проверить preconditions
python3 .harness/tools/finalize-project-init.py \
  --name '<project-name>' --check --json

# finalize
python3 .harness/tools/finalize-project-init.py \
  --name '<project-name>' --json

Exit codes: 0 — PASS/INITIALIZED, 1 — BLOCKED. Mutation атомарна: при неуспешной postcondition исходный manifest восстанавливается.

Review gates и immutable review contracts

.harness/tools/review_gates.py

Read-only preselector определяет минимально обязательные security/tests reviewers по policy, STEP type, risk flags и фактической changed surface.

python3 .harness/tools/review_gates.py STEP-042 --json

.harness/tools/review_contract.py

Проверяет implementation/planning/init/migration review history: schema, точную repository revision, verdict/findings, specialized evidence, hashes и immutable identity.

python3 .harness/tools/review_contract.py --json
python3 .harness/tools/review_contract.py --step STEP-042 --json
python3 .harness/tools/review_contract.py \
  --file planning/reviews/STEP-042/REVIEW-<timestamp>.md \
  --current-revision --json

Exit codes: 0 — PASS, 1 — FAIL.

Durable operational reports

.harness/tools/report_contract.py

Проверяет audit, release-check, skill-search и harness-update reports: schema, kind, metadata, timestamp identity и обязательные sections.

python3 .harness/tools/report_contract.py --all --json
python3 .harness/tools/report_contract.py \
  --file planning/harness-updates/UPDATE-<timestamp>.md \
  --kind harness_update --json

Exit codes: 0 — valid, 1 — invalid.

Deterministic Git preflight

.harness/tools/git-preflight.py

Read-only safety gate перед Git mutation. Проверяет strict .harness/git-policy.toml, branch/protected rules, staged/unstaged state, remote ahead/behind, PR prerequisites и Harness validation. Сам commit/push/PR/merge не выполняет; на PASS возвращает exact mutation plan.

python3 .harness/tools/git-preflight.py check --json
python3 .harness/tools/git-preflight.py \
  commit --commit-type feat --slug user-export --json
python3 .harness/tools/git-preflight.py push --json
python3 .harness/tools/git-preflight.py pr --json
python3 .harness/tools/git-preflight.py sync --json

Exit codes: 0 — PASS, 2 — BLOCKED/config/IO/Git error. --commit-type и --slug относятся только к commit preflight.

Execution Status validation

.harness/tools/execution_status.py

Управляет crash-safe local state и всегда валидирует schema при load/save: уникальные execution IDs, mode/status, root/current commands, attempt и FIX/REVIEW cycle counter. Повреждённый файл не трактуется как «нет незавершённых execution».

Self-tests проверяют сами gates

Harness содержит synthetic regression suites для command references, execution, planning contracts, reports, repository hardening, Git policy/preflight, config, self-update и update migration.

python3 .harness/tools/command-references-self-test.py
python3 .harness/tools/execution-self-test.py
python3 .harness/tools/planning-contract-self-test.py
python3 .harness/tools/report-contract-self-test.py
python3 .harness/tools/repository-hardening-self-test.py
python3 .harness/tools/git-policy-self-test.py
python3 .harness/tools/git-preflight-self-test.py
python3 .harness/tools/harness-config-self-test.py
python3 .harness/tools/harness-update-self-test.py
python3 .harness/tools/update-migration-self-test.py
Self-test PASS не проверяет текущий проект. Он доказывает только, что implementation самого gate выдержал известные positive/negative regressions.

Типовые последовательности

Перед commit

python3 .harness/tools/git-preflight.py check --json
python3 .harness/tools/validate.py --mode commit
python3 .harness/tools/git-preflight.py \
  commit --commit-type <type> --slug <slug> --json

После изменения project documents

python3 .harness/tools/sync-projections.py --check --json
python3 .harness/tools/validate.py --mode manual

При проблемах command routing

python3 .harness/tools/validate-command.py --json -- '<command-or-chain>'
python3 .harness/tools/check-command-references.py --json
