Документация Harness

Начало работы

От пустого template до project knowledge base и первого исполнимого STEP — без production code во время bootstrap.

Что нужно до старта

Harness использует Git state, diff/index и Git workflow как часть deterministic gates. Для штатного validator нужен Python 3.11+; это tooling dependency Harness, а не runtime dependency будущего продукта.

Git

Нужен для repository state, безопасных commit/push операций и traceability.

Python 3.11+

Нужен для tools/harness/validate.py, включая TOML parsing через standard-library tomllib.

1. Создайте репозиторий из template

Предпочтительный путь — GitHub Use this template. После этого клонируйте уже созданный репозиторий проекта.

Не удаляйте .project/harness.lock.json. Он хранит известный BASE текущего release и нужен будущим CHECK HARNESS UPDATE / UPDATE HARNESS. Update baseline — immutable release tag, а не moving main.

2. Опишите проект своими словами

cp PROJECT_BRIEF.example.md PROJECT_BRIEF.local.md

Brief — локальный сырой вход. Полезно указать цель, пользователей, сценарии, ограничения, обязательные или желательные технологии, out of scope и ссылки на референсы. Заранее оформлять REQ, ADR и STEP не требуется.

3. Запустите INIT PROJECT

INIT PROJECT

Initializer читает brief и создаёт project knowledge base: docs/PROJECT.md, требования, architecture baseline, roadmap и полноценные STEP-NNN. Он связывает REQ ↔ ADR ↔ STEP и заполняет scope, dependencies, acceptance criteria и verification.

INIT PROJECT не создаёт production code. Инициализация заканчивается только после consistency check и установки project.initialized: true.

4. Проверьте bootstrap

Проверьте, что требования не выдуманы, ADR не создаются «на всякий случай», зависимости не потеряны, а первые STEP действительно исполнимы.

STATUS PROJECT
NEXT STEP

5. Зафиксируйте основу

GIT CHECK
COMMIT
PUSH

Git-политика находится в .project/git-policy.toml. COMMIT и PUSH разделены: Harness не публикует изменения автоматически только потому, что реализация завершена.

6. Начните разработку

Можно идти вручную или через orchestrated flow.

Ручной flow

PLAN STEP-001
IMPLEMENT STEP-001
REVIEW STEP-001

Автоматизированный flow

RUN STEP-001
Harness сам проходит допустимые стадии и останавливается при blocker.

Новая задача формулируется обычным языком через ADD STEP: <описание>.

7. Обновляйте Harness отдельно

CHECK HARNESS UPDATE
UPDATE HARNESS

Self-update относится к maintenance protocol layer, а не к product work. Он не создаёт STEP и не делает commit/push/PR автоматически.
