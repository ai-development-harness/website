Документация Harness

Процесс разработки

Полный жизненный цикл AI-задачи: durable task contract, сохранённый plan, проверяемая реализация, независимый review и явная публикация в Git.

Workflow держится на durable handoff

История чата не является базой знаний. Каждая стадия сохраняет результат в репозитории: PLAN — в task, REVIEW — в immutable report, RECONCILE — в audit report, completion — в evidence и status projections.

Главная идея: следующая сессия должна продолжить работу из repository state, не требуя пересказа предыдущего разговора.

От запроса к task contract

ADD STEP: <описание> проверяет дубликаты, выбирает stable ID, связывает REQ/ADR, вычисляет dependencies и формирует Goal, Context, Scope, Mutation policy, Out of scope, Acceptance, Verification и Deliverables.

Production code на этом этапе не меняется.

RUN STEP: автоматический orchestrated flow

PLAN (если нет актуального плана)
  → IMPLEMENT
  → deterministic verification
  → REVIEW
  → [условно security/test review]
  → FIX ↔ REVIEW (максимум 3 цикла)
  → CLOSE

Blocker или исчерпание циклов останавливает процесс. Harness не должен маскировать failure.

Тот же процесс можно запускать вручную

PLAN STEP-NNN сохраняет технический handoff прямо в task. IMPLEMENT работает по сохранённому плану. REVIEW выполняется независимо и выпускает один из verdict: PASS, FAIL или BLOCKED.

Micro-change идёт по короткому пути

QUICK FIX: исправь опечатку…
        ↓
proportional check
        ↓
GIT CHECK
        ↓
COMMIT

QUICK FIX допустим только без изменения product/API/data/security/architecture/dependency contract. Если фактический scope больше — Harness останавливает короткий путь и предлагает ADD STEP:.

Drift не скрывается — он reconciled

RECONCILE PROJECT сравнивает code/tests/config с REQ, ADR, architecture, STEP и evidence. Результат — audit report и при необходимости corrective STEP. Production code молча не переписывается.

Публикация отделена от реализации

GIT CHECK → COMMIT → PUSH → PR

IMPLEMENT/REVIEW сами не создают commits. Git-операции имеют отдельные policy и safety checks, а force push, hard reset, автоматические merge/rebase не являются default-поведением Harness.
