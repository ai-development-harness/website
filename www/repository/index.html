Документация Harness

Репозиторий как долговременная память

Не «магическая память AI», а проверяемый проектный контекст в versioned artifacts, который можно прочитать, проверить и продолжить в новой сессии.

Память — это файлы, связи и фактическое состояние

Harness специально не использует chat history как permanent knowledge base. Новая сессия восстанавливает контекст из versioned repository artifacts: requirements, ADR, STEP, saved plan, code, tests, evidence и review reports.

Где живёт контекст

.project/                 policies, manifest, update lock
.codex/                   role/model configuration
.agents/skills/           workflow and technology skills
docs/PROJECT.md           нормализованный проектный контекст
docs/requirements/        REQ definitions + status projection
docs/adr/                 immutable architecture decisions
docs/architecture.md      current architecture baseline
planning/tasks/           canonical STEP contracts
planning/reviews/         immutable review reports
planning/audits/          reconcile/audit reports
planning/harness-updates/ self-update reports
code / tests / config     фактическая реализация

Durable handoff заменяет «помни наш прошлый чат»

ADD        → task contract
PLAN       → Implementation plan внутри STEP
IMPLEMENT  → code/tests + verification evidence
REVIEW     → immutable review report
FIX        → изменения по конкретным findings
RECONCILE  → audit report / corrective STEP

Каждый переход оставляет следующий агенту или новой сессии конкретный вход.

Git хранит историю, но Harness не сводится к commits

Git показывает что изменилось и когда. REQ/ADR/STEP/evidence добавляют зачем, в каком scope, по каким критериям и с каким результатом review. Поэтому commit history и project knowledge base дополняют друг друга.

Локальный сырой контекст остаётся локальным

PROJECT_BRIEF.local.md предназначен для незрелых идей, приватных ссылок и временных заметок и заранее исключён из Git. После INIT нормализованный контекст переносится в tracked project documentation.

Память требует reconciliation

Ручные hotfix, stale status и documentation drift неизбежны. Поэтому RECONCILE PROJECT сравнивает repository truth layers и создаёт явный audit/corrective work вместо скрытого исправления.
