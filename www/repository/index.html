Документация Harness

Репозиторий как долговременная память

Не «магическая память AI», а проверяемый проектный контекст в версионируемых артефактах, который можно прочитать, проверить и продолжить в новой сессии.

Память — это файлы, связи и фактическое состояние

Harness специально не использует историю чата как постоянную базу знаний. Новая сессия восстанавливает контекст из версионируемых артефактов репозитория: требований, ADR, STEP, сохранённого плана, кода, тестов, доказательств выполнения и отчётов ревью.

Где живёт контекст

.project/                 policies, manifest, update lock
.codex/                   Codex role/model configuration
CLAUDE.md + .claude/      Claude Code bridge and role configuration
.agents/skills/           shared workflow and technology skills
docs/PROJECT.md           нормализованный проектный контекст
docs/requirements/        REQ definitions + status projection
docs/adr/                 immutable architecture decisions
docs/architecture.md      current architecture baseline
planning/tasks/           canonical STEP contracts
planning/reviews/         immutable review reports
planning/audits/          reconcile/audit reports
planning/harness-updates/ self-update reports
code / tests / config     фактическая реализация

Runtime-specific конфигурация находится рядом с общим protocol layer, но сама память проекта не принадлежит ни Codex, ни Claude Code. Поэтому один и тот же REQ/ADR/STEP контекст может использоваться обеими интеграциями.

Сохраняемый контекст заменяет «помни наш прошлый чат»

ADD        → task contract
PLAN       → Implementation plan внутри STEP
IMPLEMENT  → code/tests + verification evidence
REVIEW     → immutable review report
FIX        → изменения по конкретным findings
RECONCILE  → audit report / corrective STEP

Каждый переход оставляет следующему агенту или новой сессии конкретный вход для продолжения работы.

Git хранит историю, но Harness не сводится к commits

Git показывает что изменилось и когда. REQ, ADR, STEP и доказательства выполнения добавляют зачем, в каких границах, по каким критериям и с каким результатом ревью. Поэтому история Git и база знаний проекта дополняют друг друга.

Локальный исходный контекст остаётся локальным

PROJECT_BRIEF.local.md предназначен для незрелых идей, приватных ссылок и временных заметок и заранее исключён из Git. После INIT нормализованный контекст переносится в отслеживаемую документацию проекта.

Память требует проверки согласованности

Ручные hotfix, устаревшие статусы и расхождения документации неизбежны. Поэтому RECONCILE PROJECT сравнивает уровни истины репозитория и создаёт явный отчёт аудита или корректирующую работу вместо скрытого исправления.
