Поддержка и обновление

Как изменять живой проект без процессного долга: короткий путь для micro-change, reconciliation drift и безопасное обновление protocol layer.

Protocol layer и product work обновляются по-разному

К Harness относятся AGENTS, core skills, execution protocol, docs/harness, policies, updater/validator и templates. Project-owned — REQ, ADR, architecture, tasks/reviews/audits, product code/tests/config и дополнительные project/third-party skills.

Для micro-change не нужен искусственный STEP

Опечатка, пунктуация, безопасный комментарий или локальное formatting могут идти через QUICK FIX или ручную правку. Git diff/commit — достаточная история такой мелочи.

Короткий путь запрещён при изменении behavior, API, schema/migrations, auth/security, dependencies, architecture boundary, существенной test strategy или requirement/acceptance criteria.

RECONCILE восстанавливает согласованность

Architecture, documentation и status drift фиксируются явно. RECONCILE PROJECT создаёт audit report и corrective STEP там, где изменение нельзя безопасно спрятать в текущий scope.

Moving main не используется как update baseline. Доступным target считается immutable release tag vMAJOR.MINOR.PATCH.

BASE / OURS / THEIRS и ownership policy

harness_owned

Локальное отличие от BASE блокирует silent overwrite.

shared

Для настраиваемых файлов выполняется 3-way merge.

marker_merge

README/AGENTS merge-ятся с сохранением generated project blocks.

unknown

По умолчанию считается project-owned и updater его не меняет.

Legacy project без lock требует adoption

Если .project/harness.lock.json отсутствует, доказуемого BASE нет. Harness не угадывает версию по похожести файлов: нужен явно известный immutable tag или ручной reconciliation.

Target release читается как данные, а не исполняется

Updater читает только allowlisted UTF-8 text files из canonical source repository. Migration/install/bootstrap scripts target release автоматически не запускаются. Новый tooling проверяется уже после inspect diff.
