Codex и Claude Code

Harness описывает процесс разработки независимо от конкретного агента для программирования. Codex и Claude Code подключаются к одному протоколу через отдельные конфигурации адаптеров.

Один протокол, две среды исполнения

Команды Harness, требования, ADR, STEP, навыки, политика Git и правила обновления не принадлежат конкретной модели. Канонический контракт репозитория хранится в AGENTS.md, а Codex и Claude Code получают собственную конфигурацию исполнения.

HARNESS PROTOCOL
AGENTS.md · REQ · ADR · STEP · skills · policies
             ↓
      runtime adapter
        ↙         ↘
     Codex     Claude Code
Можно сменить среду исполнения, не меняя смысл проекта. Состояние работы остаётся в репозитории, поэтому следующая сессия восстанавливает контекст из тех же артефактов.

Адаптер Codex

Основная конфигурация

.codex/config.toml регистрирует проектные роли и их файлы конфигурации.

Специализированные роли

.codex/agents/*.toml задают модель, уровень рассуждений, изоляцию и инструкции для каждой роли.

Модель и уровень рассуждений можно менять независимо для инициализатора, архитектора, планировщика, реализатора, проверяющего и остальных ролей. Это позволяет использовать усиленное рассуждение для архитектуры и независимого ревью, а механическую работу отдавать более экономичному профилю.

Адаптер Claude Code

Общий контракт репозитория

CLAUDE.md импортирует @AGENTS.md, поэтому правила Harness не дублируются в двух независимых файлах.

Основной профиль

.claude/settings.json задаёт проектные значения по умолчанию: модель, уровень рассуждений и базовый режим разрешений.

Специализированные роли

.claude/agents/*.md задают model, effort и permissionMode для каждой роли.

Локальные настройки

.claude/settings.local.json и CLAUDE.local.md позволяют хранить персональные настройки только для Claude вне Git.

Роли только для чтения — например архитектор, планировщик и проверяющий — по умолчанию используют режим планирования. Семантическое правило «не менять файлы» остаётся частью контракта Harness, даже если пользователь временно меняет режим основной сессии Claude Code.

Роли одинаковы по смыслу

Оба адаптера поддерживают один набор ролей Harness. Отличается только формат конфигурации среды исполнения и конкретный выбор модели.

initializer · architect · planner · implementer
reviewer · security-reviewer · test-reviewer · docs
mechanic · skill-curator · git-operator · harness-updater

В базовом профиле роли с большим объёмом рассуждений получают более сильную модель и высокий уровень рассуждений, реализатор — сбалансированный профиль, а механические роли — более дешёвый. Проект может менять эти значения под собственные ограничения.

Навыки остаются общими

Канонические навыки Harness находятся в .agents/skills/<name>/SKILL.md. Адаптер Claude не создаёт зеркальную копию базовых навыков в .claude/skills/: это избегает расхождения двух версий одного процесса. Проектные навыки только для Claude при необходимости можно добавлять отдельно.

Настройки проекта сохраняются при обновлении Harness

Отслеживаемые конфигурации ролей Codex и Claude относятся к общим файлам. HARNESS UPDATE APPLY использует трёхстороннее слияние BASE / OURS / THEIRS и не должен молча перезаписывать локальный выбор модели и уровня рассуждений. Неизвестные проектные файлы внутри каталогов адаптеров по умолчанию считаются принадлежащими проекту.

Что выбрать

Выбирайте ту среду исполнения, которой хотите пользоваться в текущей рабочей среде. Harness не требует использовать оба одновременно: достаточно одной поддерживаемой среды исполнения — Codex или Claude Code. После создания репозитория откройте его в выбранном инструменте и выполните PROJECT INIT.
